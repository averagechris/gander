# Findings

1. **major — op-picker preview and hint line invisible at ambient pane height.** Repro: 200x50 tmux pane, repo with ~25+ operations including a `jj undo` op, press `I`. The popup shows the header and op list but neither the `will mark N caught up · …` live preview nor the `↑/↓ or n/e move · enter apply · esc cancel` hint — the two things that make this feature discoverable and safe. Resize to 200x70 and both render. Cause (from source, `draw_operation_picker_popup` in `src/tui/render.rs`): `fixed_lines = 3` but 4 fixed lines are emitted, and wrapped multi-line op descriptions (undo ops embed a 128-char operation id) aren't accounted for in `list_height`, so the footer overflows the popup. This defeats the headline improvement exactly in the side-pane geometry watch mode targets.

2. **minor — stale `±` on never-viewed files that changed and changed back.** Repro: with the TUI open, append a line to an unviewed file (`src/worker.rs`), wait a poll, remove the line, wait a poll. Notice says only `src/worker.rs updated`; the `±` "changed since look" badge persists indefinitely even though content is byte-identical to launch, and selecting the file shows nothing new. Revert detection (`reverted to previously seen content`) only fires for viewed files. An agent that tries something and backs it out leaves permanent false "needs attention" flags.

3. **minor — footer notices truncate mid-word with no continuation cue.** Repro: `jj abandon @` when the abandoned change touched 2+ files; the composite notice (`@ moved … · … left range · src/config.rs updated … · tests/basic.rs u`) is cut at column 200 with no ellipsis and no "ctrl-a for more" hint. The activity feed does contain the full breakdown, but its aggregate lines truncate inside the popup too (`… src/config.r │`). New users won't know the tail exists.

4. **minor — badge taxonomy inconsistency after catch-up.** Repro: run the `I` catch-up when a file is both unchanged-since-op and flagged `±` (worker.rs above). Result: `src 6/6` viewed counts include worker.rs, but its glyph stays `±` ("changed since look") rather than `◌` or `~` ("done, changed since"). A file that simultaneously counts as viewed and displays the needs-attention flag makes the 4-glyph legend hard to trust at a glance.

5. **papercut — undo op renders as a misaligned wrapped raw id in the op picker.** Repro: press `I` in a repo with an undo op; its description wraps to a full-width unindented 128-hex-char line that breaks the id/time/description column layout and reads like a rendering error. Also the proximate trigger of finding 1's overflow.

6. **papercut — no persistent current-`@` identity in the chrome.** The footer shows `main..@ · following @` but never *which* change `@` is (id/description). Revision identity is only visible transiently in notices or by opening the activity feed; after a notice is replaced, a returning glance can't confirm what the pane is pointed at.

# Scores

- **Watch freshness/follows-@: 5/5.** Every mutation class refreshed within ~2–5s with correct content: edits, coalesced rapid edits, describe (description-only announcement, no false file churn), `jj new` (@-follow announced), abandon (including the subtle correct re-flag of config.rs whose on-disk content changed as a *consequence* of abandon), and undo (full state restoration including viewed-state and comment). Selection never jumped. Viewed-state fingerprinting is content-based and honest. The only blemish is the lack of a persistent @-identity indicator (finding 6), which slightly weakens "visibly tied to revision identity" but transitions themselves are always named.

- **Watch change awareness: 4/5.** Notices are specific (change id, file, ±delta, viewed-impact), reverted-viewed-content is called out, the timestamped activity feed gives a real audit trail, and the op-picker catch-up with live preview is exactly the "what needs fresh review since op X" primitive an ambient reviewer needs. Held at 4 rather than 5 because: the flagship preview/hint is invisible at pane height (finding 1), notices truncate without a cue (finding 3), never-viewed revert-to-original leaves permanently stale `±` (finding 2), and there is no jump-from-notice/feed-entry-to-file navigation.

- **Pane-worthiness: 4/5.** I would leave this open all day next to an agent: it never went stale, never lost my review state, survived history rewriting, and — critically for coexistence with an agent — leaves a clean op log with zero idle snapshots. What keeps it from 5 is trust erosion at the margins: stale `±` flags after back-and-forth agent edits mean "flagged" doesn't reliably mean "something to see", the truncated notices lose the tail of exactly the busiest events, and the catch-up workflow's UI is hidden at realistic pane sizes.

# Top proposals

1. **Fix op-picker popup layout at small heights** (finding 1): count 4 fixed lines, measure wrapped description heights (or truncate descriptions to one column-aligned line — which also fixes finding 5), and shrink the op list window so the preview and hint are always visible. This is the single highest-leverage fix; the feature is excellent and currently invisible.
2. **Extend revert detection to unviewed files / net-zero deltas** (finding 2): track fingerprints since last look for all files, and clear `±` (with a `reverted` notice) whenever content returns to the last-seen state, viewed or not. Ambient agents constantly try-and-revert; false flags are the fastest way to make a reviewer stop trusting badges.
3. **Make notices overflow-aware**: ellipsize with a visible `… (ctrl-a)` suffix when a notice exceeds the pane width, and wrap (not clip) aggregate lines inside the activity feed.
4. **Persistent @-identity chip** in the footer or files-pane title (`@ ukqsyyxs chore: tune test config comments`), so a glance always confirms what is being watched without relying on the last transient notice.
5. **Notice/feed → navigation**: from the activity feed (or via a key on the latest notice), jump directly to the file/hunk an event names — closing the loop from "something changed" to "I'm looking at it".
